# potalk-cli

[ぽっと通話 (po-talk.github.io)](https://github.com/po-talk/po-talk.github.io) の派生CLI版です。

## これはなに？

ブラウザベースで動く「ぽっと通話」のコア機能と外見を分離してみたらどうなるか？というテストの一環として作成した、ターミナル向けのクライアント（CLI版）です。

vimjpやNostrのどこかに生息しているであろう、黒い画面を愛する**Vimmerに向けた熱いラブコール**でもあります（笑）。

## なぜ Node.js なのか？

GoやRustといった渋い言語も検討しましたが、動いている元のHTML/JavaScriptからコードやモジュールを「うまく拝借（移植）」しながらスピーディーに形にするため、今回は **Node.js** を選択しました。

## インストール

Node.js **20.6以上**が必要です。ネイティブWebRTC依存の対応範囲に合わせ、Node.js 22を推奨します。音声を聞く・話すには SoX の `play`・`rec` コマンドも必要です。

Windows・macOS・Linuxの詳しい手順（Node.js、SoX、インストール、起動確認）は[OS別の導入ガイド](docs/install.md)を参照してください。

リポジトリを取得して依存関係をインストールします。

```bash
git clone https://github.com/Mitsuru-Tagami/potalk-cli.git
cd potalk-cli
npm ci
npm link          # ptk コマンドとして使えるようにする（任意）
ptk help
```

`npm link` を使わない場合は、リポジトリ内で `node ptk.mjs help` のように実行できます。

## 使い方

```bash
ptk               # ロビーを TUI で表示（j/k で移動、Enter で部屋に入る、/ で絞り込み、r で再読み込み、q で終了）
ptk list          # 通話中の部屋を一覧で出力（--seconds N で待ち時間、既定 15 秒）
ptk join          # ロビーから番号で選んで部屋に入る
ptk join 'https://potalk.app/#room=…&name=…'   # 招待リンクで入る
ptk join アサ      # 名前の一部で入る（部屋名・話題タグ・いる人の名前。複数合えば番号で選ぶ）
ptk create 部屋名  # 新しい部屋を作って入る（部屋名を省くと「あなたの名前の部屋」）
ptk join 'https://potalk.app/#room=…&name=…' --events-jsonl  # 受信コメントをJSON Linesで標準出力へ
ptk join 'https://potalk.app/#room=…&name=…' --tts 'espeak-ng -v ja'  # Linuxの例
ptk --tts 'say -v Kyoko'  # macOSの例（TUIで部屋に入った後も有効）
ptk help
```

`--name 名前`・`--emoji 絵文字` で名乗れます（`ptk`・`join`・`create` のどれでも）。**一度付ければ覚えて、次からは付けなくてもその名前**になります（`~/.config/ptk/profile.json`）。名乗らなければ、最初に「深煎りキリマンジャロ」のようなコーヒーの名前を自動で付けます。音を鳴らしたくないときは `--no-sound` を付けます。
木の芽は部屋への参加回数・別々の日に使った日数・累積滞在時間で育ちます。🌿は参加3回・累積5分、🌷／🌻は4日・10回・60分、🌲／🌳は14日・20回・180分が条件です。花と木は平均滞在時間が12分未満なら🌷／🌲、12分以上なら🌻／🌳になります。滞在時間は通話中30秒ごとに加算されます。記録は `~/.config/ptk/growth.json` に保存され、ブラウザ版の記録とは別です（`XDG_CONFIG_HOME` を設定している場合はその配下）。
TUI のロビーで `/` を押すと、部屋名・話題タグ・いる人の名前で絞り込めます（Enter で確定、Esc で解除。ひらがな／カタカナ、全角／半角は区別しません）。
TUI の部屋の画面では、参加者（話している人に 🔊）・お知らせ・入力欄が並びます。`i` か Enter で入力欄に入り、ひとことを打って Enter で送ります（60 文字まで）。入力中は Tab でコマンド補完できます。`t` でマイクのオン・オフ、`m` で音を消す・戻す、`q` で退出してロビーへ戻ります。`b` または Esc を短時間に2回押すと週次メモ画面へ切り替わります。
TUIの通話中に `/boss` を実行しても週次メモ風の画面に切り替わり、任意のキー入力で元の画面に戻ります。Esc単独では起動せず、入力欄のEscキャンセルや名刺編集ダイアログの操作を優先します。マウスでは戻らず、画面を隠している間も通話・チャットは続きます（`ptk join` の行表示では利用できません）。
部屋の中では、入力欄（行表示ならそのまま）に `/tag 新しい話題` で話題を変えられ（`/notag` で消す）、`/list` で部屋にいるままほかの部屋の一覧を見られます。`/cp`（または `/copy`）で現在の部屋URLをクリップボードへコピーできます。`/card` はひとこと・X/GitHub/note/Instagram/YouTube/Nostr・お礼窓口（OFUSE/Amazon/Zap/Ko-fi/Buy Me a Coffee）・画像data URLを対話形式で登録します。IDのほか対応するプロフィールURLも入力できます。画像はあらかじめ128×128px以下に縮小し、WebP/JPEG/PNGのdata URLにしてください。各項目は空Enterで維持し、`-` で削除できます。`/who` で参加者番号を確認し、`/card 2` のように指定するとその相手にだけ名刺を要求します。名刺本文には署名しません。公開鍵があればpeerIdを含むチャレンジで「現在の接続相手がカード鍵に応答できること」だけを確認し、応答がない場合もカードを未検証として表示します。通常の `/card 2` はSNSへ照会せず、証拠も照合したい場合だけ `/card 2 --verify` を実行してください。名刺鍵のチャレンジ成功後にX・GitHubへ照会し（照合先に接続元IPが伝わる場合があります）、Nostr証拠は端末内で署名検証します。証拠なし・不一致・通信失敗は確認済みにしません。
`ptk join` の行表示では、文字を打って Enter でひとことを送ります。Tab でコマンドを補完できます。`/mic` でマイクのオン・オフ、`/who` で参加者（話している人に 🔊）、`/mute` で音を消す・戻す、`/cp` でURLをコピー、`/q`（または Ctrl-C）で退出します。

`/dice` は6面、`/dice 20` は20面のダイスを振り、出目を自分の発言として部屋に送信します。`--tts` を設定している場合は自端末でも読み上げ、受信側では通常の受信コメントとして既存のTTS経路に渡ります。`--events-jsonl` は引き続き相手から受信したコメントだけを出力するため、自分の出目は送信側のJSONLには混ざりません。面数は1以上の整数を指定してください。

`/waka` は国文学研究資料館がCC BY 4.0で公開する嘉禄二年本『古今和歌集』TEI/XMLから一首を、`/haiku` は松山市のCC BYデータ「正岡子規の俳句（季節別）」から一句をランダムに選び、作者と短い出典表示を添えて部屋に送信します。`/dice` と同じ送信・TTS経路を使い、送信側の `--events-jsonl` には含めません。古典本文は一行に整え、作者名・出典込みで60文字以内に収まる候補だけを選ぶため、送信時に切り詰めません。データの出典、抽出・整形内容、ライセンス、帰属表示は[句データの出典とライセンス](docs/poem-data-sources.md)を参照してください。

`/seiza` は国際天文学連合が定める88星座から一つを選び、星座名の由来や表すものを短く解説します（例：`/seiza オリオン座`。名前は「座」を省略して指定でき、ラテン名や略符でも検索できます）。`/uranai` はこれまでの12星座占いを独立したコマンドとして引き継ぎ、`/uranai 牡羊座` のように指定できます（星座名を省くとランダム選択）。`/omikuji` は従来どおり大吉・吉・中吉・小吉・末吉・凶から運勢を選び、ひとことと今日の小さな提案を添えます。占いは娯楽向けの短い読み物です。各結果は一行・60文字以内で、送信・TTSはほかのチャットコマンドと同じ経路を使い、送信側の `--events-jsonl` には含めません。星座名と解説データの出典は[88星座データの出典](docs/constellation-data.md)を参照してください。

`/who` の参加者番号を使い、`/hbk <番号>` で相手をローカルミュート、`/unhbk <番号>` で解除できます（自分は1番）。対象は表示名ではなく、その接続の `peerId` です。ミュートした相手のチャットは画面表示・`--events-jsonl`・`--tts` のいずれにも流さず、音声は再生中のトラックを切り離し、新しいトラックも再生しません。解除すると保持している最新トラックを再接続します。入退室などの通知は通常どおり残り、ミュート状態を相手へ通知しません。状態は退出時に破棄されます。これは通信を止めるブロック機能ではなく、この端末で表示・再生しないための機能です。

`ptk join` または `ptk create` に `--events-jsonl` を付けると、**相手から受信したチャットコメントだけ**を標準出力へJSON Linesで出力します。各行は `{"type":"chat","from":"💻表示名","text":"コメント本文"}` 形式です。システム通知や自分が送った発言は含みません。このモードでは通常の画面表示・操作プロンプトは標準エラーへ出るため、標準出力を外部スクリプトへパイプできます。

`--tts <コマンド>` を付けると、受信したチャットの **本文だけ** を外部コマンドの標準入力へ渡して読み上げます。たとえば Linux では `--tts 'espeak-ng -v ja'`、macOS では `--tts 'say -v Kyoko'` のように指定します。`ptk join` / `ptk create` のほか、ロビーTUIを起動する `ptk --tts 'say -v Kyoko'` でも使えます。TTSエンジンや辞書は含まれず、未指定時は読み上げません。

TTSコマンドはシェルを介さず起動し、空白区切りと引用符で実行ファイル・引数を指定します（パイプやリダイレクト等のシェル構文は使えません）。子プロセスは非同期で、標準出力・標準エラーを破棄します。読み上げを順番に処理するため、受信・入力・画面表示や `--events-jsonl` のJSONL出力は待たされません。コマンドが見つからない、または途中で失敗した場合は、その読み上げだけを諦めてCLIは継続します。

VOICEVOXまたはCOEIROINK v2で読み上げる場合は、まず[かんたんセットアップ](docs/tts-quickstart.md)を使ってください。稼働中のエンジンと声を番号で選ぶだけで、設定ファイルや話者IDの手編集は不要です。エンジン本体と音声ライブラリは別途用意・起動してください。

エンジンの導入やAPIの手動設定は、[VOICEVOXガイド](docs/voicevox-tts.md)・[COEIROINK v2ガイド](docs/coeiroink-tts.md)を参照してください。従来の複雑なJSONルーター設定は[上級者向けガイド](docs/multi-tts-router.md)にあります。

po-talk のブラウザ版と同じロビー・同じ Nostr リレーに乗り入れているので、ブラウザ版で通話中の部屋がそのまま見え、同じ部屋に入れます。

部屋の中では「参加者を見る・**声を聞く**・**話す**・**ひとことを読む／書く**・話題タグを見る」ができます。
配信部屋では聞き役として入り、配信者と、配信者が許可した人の声が聞こえます（話すことはできません）。

> [!WARNING]
> **CLI を使うと、あなたの IP アドレスが相手から見えます。**
> po-talk のブラウザ版は TURN 中継を通すので相手に IP が見えませんが、CLI はまだ TURN を使えず、相手と直接つなぎます（STUN のみ）。
> 同じ部屋の人だけでなく、ロビーを開いているブラウザからも見えます。気になる場合は使わないでください（[#2](https://github.com/Mitsuru-Tagami/potalk-cli/issues/2)）。

### しくみのメモ

- WebRTC は [@roamhq/wrtc](https://github.com/WonderInventions/node-webrtc)（Chromium と同じ libwebrtc）を使っています。
  po-talk は部屋の全員から音が届く前提なので、CLI はマイクの代わりに**無音の音声トラック**を送ります（ブラウザからは「ミュート中の人」に見えます）。
  配信部屋では聞き役として入るので、音は送りません。
- 相手の声は、wrtc がデコードした音（PCM）を相手ごとに混ぜて、sox の `play` に流して鳴らしています。
- 自分の声は、sox の `rec` でマイクの音を取り、無音のかわりに送っています。**マイクは入るときオフ**で、オンにしている間だけ `rec` が動きます。
  ブラウザと違ってエコーを消す仕組みが無いので、**ヘッドホンを使ってください**（スピーカーだと相手の声が相手に返ります）。
  macOS では、初めてオンにしたときにターミナルのマイク使用の許可を求められます。
- 配信部屋の声は、po-talk と同じく「配信者が許可した人」の分だけを鳴らします。許可は、配信者が自分の秘密鍵で署名した名簿で配られ、
  CLI は公開鍵が部屋 ID の指紋と合うこと・署名・時刻（古い名簿の使い回し）を確かめてから従います（`lib/roster.mjs`）。
  名簿に載っていない人の声は、改造クライアントから送られてきても鳴らしません。
- 配信者の `peerId` も本人確認されるまで信頼せず、`oath` のチャレンジ応答を採用済み名簿の公開鍵で検証してから、その人の音声を再生します（`lib/oath.mjs`）。CLI は聞き役としての対応で、配信者側の鍵・署名機能は持ちません。
- 名刺は本家本番と同じ `card` actionで要求された相手1人だけに送ります。応答は `{k:'res', bio?, avatar?, socials?, tip?, ck?, pr?}` で、`pr` はX/GitHub/Nostrの本人確認証拠であり、本文署名ではありません。通常の取得では外部照会せず、一括した「本人確認済み」とも表示しません。`/card <番号> --verify` の明示時だけ、鍵応答成功後に本家の証拠を照合します。`ck`があれば `card\n部屋ID\n要求側peerId\n応答側peerId\nnonce` に対するP-256/SHA-256・IEEE P1363署名を確かめますが、これは接続相手のカード鍵所持応答だけを示し、カード本文・人・SNSアカウントの真正性は証明しません。確認に失敗したカードも未検証として表示します。
- `/card <番号> --verify` は、名刺鍵の応答確認が成功した場合だけ本家仕様のSNS証拠を照合します。成功表示はSNSアカウントと名刺鍵の結び付きを示すもので、アカウント所有者の実名・人間としての身元・名刺のひとこと等の真偽は確認しません。

  | SNS | 照合内容 | 確認できること／できないこと |
  | --- | --- | --- |
  | X | `pr.x` の投稿をoEmbedで取得し、応答の `author_url` が `socials.x` と一致することと投稿本文に鍵指紋行があることを確認 | そのXアカウントが名刺鍵指紋を含む投稿を公開したこと。実名や他の記載内容は確認しません。 |
  | GitHub | `pr.github: 1` がある場合、プロフィールAPIの `login` が `socials.github` と一致し、bioに鍵指紋行があることを確認 | そのGitHubプロフィールのbioが名刺鍵指紋を掲示していること。実名や他の記載内容は確認しません。 |
  | Nostr | `socials.nostr` のnpubとイベントpubkeyの一致、kind 30078・`d=potalk-card`・鍵指紋行、およびNIP-01 ID/署名を検証 | 対応するNostr秘密鍵が名刺鍵指紋を含む証拠イベントに署名したこと。実名や他の記載内容は確認しません。 |
  | note・Instagram・YouTube | 本家プロトコルに照合可能な証明方式がありません | IDは自己申告のままです（YouTubeの照合も本家で未定義）。確認済みにはしません。 |

- 名刺本文は署名されません。ひとこと・アイコン・SNS ID・お礼窓口は受け取った側で真偽を確認できず、お礼窓口は本人申告のままです。SNS照合失敗・タイムアウト・proof欠落は確認済みにしません。
- 名刺データは `~/.config/ptk/card.json`、鍵は別ファイル `~/.config/ptk/card-key.json`（0600）に保存します（`XDG_CONFIG_HOME` 利用時はその配下）。ローカルのCLI鍵はOSファイルで保護しており、ブラウザ版の取り出せない鍵と同じ保護特性ではありません。SNS照合は明示的な `--verify` 時だけ行い、X/GitHubには接続元IPが伝わる場合があります。Nostr証拠は端末内で検証します。
- 部屋にいる間は、po-talk と同じくロビーへ在室を告知します（秘密の部屋を作れないようにする po-talk の決まり）。
