# potalk-cli

[ぽっと通話 (po-talk.github.io)](https://github.com/po-talk/po-talk.github.io) の派生CLI版です。

## これはなに？

ブラウザベースで動く「ぽっと通話」のコア機能と外見を分離してみたらどうなるか？というテストの一環として作成した、ターミナル向けのクライアント（CLI版）です。

vimjpやNostrのどこかに生息しているであろう、黒い画面を愛する**Vimmerに向けた熱いラブコール**でもあります（笑）。

## なぜ Node.js なのか？

GoやRustといった渋い言語も検討しましたが、動いている元のHTML/JavaScriptからコードやモジュールを「うまく拝借（移植）」しながらスピーディーに形にするため、今回は **Node.js** を選択しました。

## 使い方

Node.js 20.6 以上が必要です。声を聞く・話すには [sox](https://sourceforge.net/projects/sox/) も入れてください（`brew install sox` / `apt install sox`）。

```bash
npm install
npm link          # ptk コマンドとして使えるようにする（任意）

ptk               # ロビーを TUI で表示（j/k で移動、Enter で部屋に入る、/ で絞り込み、r で再読み込み、q で終了）
ptk list          # 通話中の部屋を一覧で出力（--seconds N で待ち時間、既定 15 秒）
ptk join          # ロビーから番号で選んで部屋に入る
ptk join 'https://potalk.app/#room=…&name=…'   # 招待リンクで入る
ptk join アサ      # 名前の一部で入る（部屋名・話題タグ・いる人の名前。複数合えば番号で選ぶ）
ptk create 部屋名  # 新しい部屋を作って入る（部屋名を省くと「あなたの名前の部屋」）
ptk join 'https://potalk.app/#room=…&name=…' --events-jsonl  # 受信コメントをJSON Linesで標準出力へ
ptk join 'https://potalk.app/#room=…&name=…' --tts 'espeak-ng -v ja'  # Linuxの例
ptk --tts 'say -v Kyoko'  # macOSの例（TUIで部屋に入った後も有効）
ptk help
```

`--name 名前`・`--emoji 絵文字` で名乗れます（`ptk`・`join`・`create` のどれでも）。**一度付ければ覚えて、次からは付けなくてもその名前**になります（`~/.config/ptk/profile.json`）。名乗らなければ、最初に「深煎りキリマンジャロ」のようなコーヒーの名前を自動で付けます。音を鳴らしたくないときは `--no-sound` を付けます。
木の芽は部屋への参加回数・別々の日に使った日数・累積滞在時間で育ちます。🌿は参加3回・累積5分、🌷／🌻は4日・10回・60分、🌲／🌳は14日・20回・180分が条件です。花と木は平均滞在時間が12分未満なら🌷／🌲、12分以上なら🌻／🌳になります。滞在時間は通話中30秒ごとに加算されます。記録は `~/.config/ptk/growth.json` に保存され、ブラウザ版の記録とは別です（`XDG_CONFIG_HOME` を設定している場合はその配下）。
TUI のロビーで `/` を押すと、部屋名・話題タグ・いる人の名前で絞り込めます（Enter で確定、Esc で解除。ひらがな／カタカナ、全角／半角は区別しません）。
TUI の部屋の画面では、参加者（話している人に 🔊）・お知らせ・入力欄が並びます。`i` か Enter で入力欄に入り、ひとことを打って Enter で送ります（60 文字まで）。入力中は Tab でコマンド補完できます。`t` でマイクのオン・オフ、`m` で音を消す・戻す、`q` で退出してロビーへ戻ります。
部屋の中では、入力欄（行表示ならそのまま）に `/tag 新しい話題` で話題を変えられ（`/notag` で消す）、`/list` で部屋にいるままほかの部屋の一覧を見られます。`/cp`（または `/copy`）で現在の部屋URLをクリップボードへコピーできます。`/card` はひとこと・X/GitHub/note/NostrのID・お礼の窓口・画像data URLを対話形式で登録します。画像はあらかじめ128×128px以下に縮小し、WebP/JPEG/PNGのdata URLにしてください。各項目は空Enterで維持し、`-` で削除できます。`/who` で参加者番号を確認し、`/card 2` のように指定するとその相手にだけ名刺を要求します。署名とpeerIdを結んだチャレンジ応答が確認されるまでカード本文は表示しません。
`ptk join` の行表示では、文字を打って Enter でひとことを送ります。Tab でコマンドを補完できます。`/mic` でマイクのオン・オフ、`/who` で参加者（話している人に 🔊）、`/mute` で音を消す・戻す、`/cp` でURLをコピー、`/q`（または Ctrl-C）で退出します。

`ptk join` または `ptk create` に `--events-jsonl` を付けると、**相手から受信したチャットコメントだけ**を標準出力へJSON Linesで出力します。各行は `{"type":"chat","from":"💻表示名","text":"コメント本文"}` 形式です。システム通知や自分が送った発言は含みません。このモードでは通常の画面表示・操作プロンプトは標準エラーへ出るため、標準出力を外部スクリプトへパイプできます。

`--tts <コマンド>` を付けると、受信したチャットの **本文だけ** を外部コマンドの標準入力へ渡して読み上げます。たとえば Linux では `--tts 'espeak-ng -v ja'`、macOS では `--tts 'say -v Kyoko'` のように指定します。`ptk join` / `ptk create` のほか、ロビーTUIを起動する `ptk --tts 'say -v Kyoko'` でも使えます。TTSエンジンや辞書は含まれず、未指定時は読み上げません。

TTSコマンドはシェルを介さず起動し、空白区切りと引用符で実行ファイル・引数を指定します（パイプやリダイレクト等のシェル構文は使えません）。子プロセスは非同期で、標準出力・標準エラーを破棄します。読み上げを順番に処理するため、受信・入力・画面表示や `--events-jsonl` のJSONL出力は待たされません。コマンドが見つからない、または途中で失敗した場合は、その読み上げだけを諦めてCLIは継続します。

Linux MintでVOICEVOX Engineを使う場合は、[セットアップ手順](docs/voicevox-tts.md)を参照してください。Engineと音声ライブラリは別途用意・起動します。
Linux MintでCOEIROINK v2を使う場合は、[セットアップ手順](docs/coeiroink-tts.md)を参照してください。COEIROINK本体と音声ライブラリは別途用意・起動します（Pythonラッパーは同梱）。

po-talk のブラウザ版と同じロビー・同じ Nostr リレーに乗り入れているので、ブラウザ版で通話中の部屋がそのまま見え、同じ部屋に入れます。
部屋の中では「参加者を見る・**声を聞く**・**話す**・**ひとことを読む／書く**・話題タグを見る」ができます。
配信部屋では聞き役として入り、配信者と、配信者が許可した人の声が聞こえます（話すことはできません）。

> [!WARNING]
> **CLI を使うと、あなたの IP アドレスが相手から見えます。**
> po-talk のブラウザ版は TURN 中継を通すので相手に IP が見えませんが、CLI はまだ TURN を使えず、相手と直接つなぎます（STUN のみ）。
> 同じ部屋の人だけでなく、ロビーを開いているブラウザからも見えます。気になる場合は使わないでください（[#2](https://github.com/Mitsuru-Tagami/potalk-cli/issues/2)）。

### しくみのメモ

- WebRTC は [@roamhq/wrtc](https://github.com/WonderInventions/node-webrtc)（Chromium と同じ libwebrtc）を使っています。
  po-talk は部屋の全員から音が届く前提なので、CLI はマイクの代わりに**無音の音声トラック**を送ります（ブラウザからは「ミュート中の人」に見えます）。
  配信部屋では聞き役として入るので、音は送りません。
- 相手の声は、wrtc がデコードした音（PCM）を相手ごとに混ぜて、sox の `play` に流して鳴らしています。
- 自分の声は、sox の `rec` でマイクの音を取り、無音のかわりに送っています。**マイクは入るときオフ**で、オンにしている間だけ `rec` が動きます。
  ブラウザと違ってエコーを消す仕組みが無いので、**ヘッドホンを使ってください**（スピーカーだと相手の声が相手に返ります）。
  macOS では、初めてオンにしたときにターミナルのマイク使用の許可を求められます。
- 配信部屋の声は、po-talk と同じく「配信者が許可した人」の分だけを鳴らします。許可は、配信者が自分の秘密鍵で署名した名簿で配られ、
  CLI は公開鍵が部屋 ID の指紋と合うこと・署名・時刻（古い名簿の使い回し）を確かめてから従います（`lib/roster.mjs`）。
  名簿に載っていない人の声は、改造クライアントから送られてきても鳴らしません。
- 配信者の `peerId` も本人確認されるまで信頼せず、`oath` のチャレンジ応答を採用済み名簿の公開鍵で検証してから、その人の音声を再生します（`lib/oath.mjs`）。CLI は聞き役としての対応で、配信者側の鍵・署名機能は持ちません。
- 名刺は `card` actionで要求された相手1人だけに送り、本文をECDSA P-256 / SHA-256署名（IEEE P1363、base64url）します。公開鍵 `ck` と本文署名 `pr`、および `card\n部屋ID\n要求側peerId\n応答側peerId\nnonce` の応答署名を受信側で検証し、不一致なら破棄します。プロフィールJSONは `~/.config/ptk/card.json`、秘密鍵は別ファイル `~/.config/ptk/card-key.json`（0600）に保存します（`XDG_CONFIG_HOME` 利用時はその配下）。
- 署名は「その秘密鍵の持ち主がこの内容に署名した」ことと、カードJSONの直接編集を検出するものです。カードの記載内容が事実であることや、端末管理者が秘密鍵を使って虚偽の内容に再署名することまでは防げません。SNSの所有確認もこのCLIでは行わず、リンクやお礼窓口は本人申告です。
- 部屋にいる間は、po-talk と同じくロビーへ在室を告知します（秘密の部屋を作れないようにする po-talk の決まり）。

## 開発

```bash
npm test          # 自動テスト（ネットワークは使いません）
```

`trystero`・`@roamhq/wrtc`・`blessed` は、内部の作りに頼った回避策があるので版を固定しています（`lib/polyfill.mjs`・`lib/tui.mjs`）。上げるときは `npm test` で確かめてください。
